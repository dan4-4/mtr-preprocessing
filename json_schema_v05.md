# JSON-схема данных пилота (v0.5)

## Принцип

Схема минимальна: только поля, необходимые для проверки гипотезы пилота. Каждый объект — одна позиция ведомости на определённой стадии обработки.

## Пайплайн и владельцы

```
─── ПРЕПРОЦЕССИНГ (Даня) ──────────────────────────────────────────

  Стадия 0: Excel → ResourceItem          (Даня, CODE)
            парсинг 10 полей + regex КСР-кода + поиск по КСР-коду в справочнике

  Стадия 1: ResourceItem → NormalizedItem  (Даня, CODE + LLM + каталог)
            извлечение характеристик (regex) + нормализация названия (LLM)
            + поиск по каталогу

─── ПОИСК И СОПОСТАВЛЕНИЕ (Федя) ──────────────────────────────────

  Стадия 4: NormalizedItem → WebQuote      (Федя, SEARCH + CODE + LLM)
            парсинг сайтов + скриншоты

  Стадия 5: WebQuote → MatchResult         (Федя, LLM)
            сопоставление: аналог ли найденное?

─── ЗАПРОСЫ ПОСТАВЩИКАМ (Артём) ───────────────────────────────────

  Стадия 2: NormalizedItem → RequestForm   (Артём, CODE + LLM)
            генерация Excel-запросов по шаблону и отправку по email

  Стадия 3: ответ → SupplierQuote           (Артём, CODE + LLM)
            приём + валидация ответов поставщиков

─── РАСЧЁТЫ И ОТЧЁТ (Даня) ────────────────────────────────────────

  Стадия 6: WebQuote + SupplierQuote → CalculatedPrice   (Даня, CODE)
            фильтр выбросов + средняя + валюты

  Стадия 7: CalculatedPrice → ReportRow    (Даня, CODE)
            склейка отчёта по Шаблону
```

Сквозной ключ — `item_id` (генерирует Даня на стадии 0).

**Стыки передачи данных:**
1. Даня → Федя: `NormalizedItem[]` (после стадии 1)
2. Даня → Артём: `NormalizedItem[]` (та же посылка, после стадии 1)
3. Федя → Даня: `WebQuote[]` + `MatchResult[]` (после стадии 5)
4. Артём → Даня: `SupplierQuote[]` (после стадии 3)

---

## Каталог материалов

**Источник:** `Пример отчета мониторинга цен.xlsx` (от заказчика 27.08.2026).
- Колонка F — исходное наименование ресурса.
- Колонки P (Наименование 1), V (Наименование 2), AB (Наименование 3) — нормализованные наименования от поставщиков.

**Покрытие:** из 19 304 строк: P — 727 (3.8%), V — 132 (0.7%), AB — 43 (0.2%).

**Использование:** на стадии 1 (нормализация) LLM получает на вход не только `name_raw`, но и список похожих наименований из каталога. Найденное нормализованное наименование используется как эталон.

## Стадия 0 — ResourceItem (Даня, CODE)

Источник: `Тестовый.xlsx` (выборка 60 позиций из `2_Исходная таблица.xlsx`).

```json
{
  "item_id": "raw-0001",
  "ks_number": 1,
  "estimate_code": "ЛСР-03-05-203ТМ",
  "resource_type": 3,
  "justification_source": "ТЦ_18.1.06.00_50_.../ КА п.70/ ЗАО «Сибгазстройдеталь» №897",
  "ksr_code": "01.7.15.02-0036",
  "ksr_name": "Болты анкерные с гайкой стальные фрикционные расклинивающиеся...",
  "name_raw": "Запорная арматура По типу 1156-125-М DN 125; pmax=1.10 MPag; tmax=40 °С; ...",
  "unit_raw": "шт.",
  "consumption": 16,
  "base_price": 226407.66,
  "total_cost": 3622522.56
}
```

**КСР-код:**
- `ksr_code` извлекается regex `\d+\.\d+\.\d+\.\d+-\d+` из колонки «Обоснование». Если кода нет — `null`.
- `ksr_name` — наименование из `Выгрузка КСР.xlsx` (lookup по `ksr_code`). Если не найден — `null`.
- 47/60 строк (78%) содержат КСР-код; 32/47 (68%) найдены в справочнике.

## Стадия 1 — NormalizedItem (Даня, CODE + LLM + каталог)

Наследует всё из ResourceItem + добавляет нормализованные поля.

```json
{
  "item_id": "raw-0001",

  "name_raw": "...",
  "name_normalized": "Запорная арматура DN 125",

  "ksr_code": "01.7.15.02-0036",
  "ksr_name": "Болты анкерные с гайкой стальные фрикционные расклинивающиеся...",

  "catalog_matches": [
    "Запорная арматура DN125 клапан запорный",
    "Клапан запорный ручной DN 15"
  ],

  "characteristics": {
    "material_type": "арматура запорная",
    "material": null,
    "grade": "1156-125-М",
    "dn": "DN 125",
    "peak_pressure": "1.10 MPag",
    "max_temperature": "40 °С",
    "working_medium": "Вода химически обессоленная",
    "safety_class": "4Н",
    "connection_type": "Под приварку",
    "dimensions": null,
    "standards": []
  },

  "unit_raw": "шт.",
  "unit_normalized": "шт",

  "confidence": 0.92,
  "normalization_method": "code+llm",
  "catalog_used": true,
  "notes": null
}
```

**Два слоя нормализации:**

**Слой A — детерминированный (CODE, regex):**
- Извлечение DN, pmax, tmax, рабочей среды, класса безопасности, способа присоединения по известным паттернам.
- Паттерны: `DN \d+`, `pmax=[\d.]+ MPag`, `tmax=\d+ °С`, `Раб\. среда:(.+?);`, `Кл\.?\s*[\dН]+`, `Тип присоединения:(.+?)[;.]`.
- 181 строка с DN, 133 с рабочей средой, 12 с pmax — regex извлекает надёжнее LLM.
- `normalization_method` = `"code"` если все характеристики извлечены regex.

**Слой B — семантический (LLM):**
- Очистка наименования: отделить название от характеристик (`Запорная арматура По типу 1156-125-М DN 125; ...` → `Запорная арматура`).
- Определение `material_type` (категория материала).
- Поиск по каталогу (`catalog_matches`).
- `confidence` — оценка LLM.
- `normalization_method` = `"code+llm"` если использован LLM.

**Правила:**
- Поля в `characteristics` заполняются только если значение есть в `name_raw`. Нет в тексте → `null`.
- `standards` — массив; извлекается из наименования (ГОСТ/ТУ/EN/ASTM). В выборке почти нет.
- Если regex не нашёл характеристику, а LLM может вывести её семантически — LLM заполняет с пометкой в `notes`.
- `catalog_matches` — список похожих наименований из каталога материалов (колонки P/V/AB). Пустой массив, если совпадений нет.

## Стадия 2 — RequestForm (Артём, CODE)

Маппинг NormalizedItem → 7 колонок «Приложения к запросу»:

| Колонка шаблона | Поле JSON |
|---|---|
| № п/п | порядковый |
| Код ресурса | `ks_number` + `estimate_code` |
| Наименование | `name_normalized` |
| Марка/класс | `characteristics.grade` |
| Тех. характеристики | сборка из `characteristics.*` (кроме grade и standards) |
| Стандарт | `characteristics.standards` (join) |
| Ед.изм. | `unit_normalized` |

Колонки 8–14 пустые — заполняет поставщик.

## Стадия 3 — SupplierQuote (Артём, LLM + CODE)

Ответ поставщика из заполненного шаблона (колонки 8–14 + шапка).

```json
{
  "quote_id": "sup-0001-A",
  "item_id": "raw-0001",

  "supplier_company": "OOO СтройАрматура",
  "quote_date": "2026-09-05",
  "price_valid_until": "2026-10-05",

  "proposed_name": "Клапан запорный 1156-125-М DN125",
  "plant_location": "Москва",
  "currency": "RUB",
  "unit_price_excl_vat": 210000,
  "transportation_cost": null,
  "insurance_charges": null,
  "notes": null,

  "validation_status": "valid"
}
```

Валидация (CODE): обязательны `proposed_name`, `currency`, `unit_price_excl_vat`. Цена — число, валюта — из справочника.

```json
{
  "quote_id": "web-0001-A",
  "item_id": "raw-0001",

  "proposed_name": "Арматура запорная DN125 1с-11-...",
  "unit_price": 215000,
  "currency": "RUB",
  "unit": "шт",
  "price_date": "2026-08-20",
  "supplier": "Металлоторг",
  "source_url": "https://...",
  "source_type": "site",

  "screenshot_path": "2026.08.20_Запорная арматура DN125.png",
  "screenshot_date": "2026-08-20"
}
```

**Скриншоты:**
- `screenshot_path` — имя файла: `ГГГГ.ММ.ДД_наименование позиции (сокращённое).png`.
- Без QR-кода.
- Программная задача (захват страницы браузером).

## Стадия 5 — MatchResult (Федя, LLM)

Сопоставление: является ли найденное предложение аналогом искомой позиции.

```json
{
  "match_id": "m-0001-1",
  "item_id": "raw-0001",
  "quote_id": "web-0001-A",
  "quote_source": "web",

  "equivalence_level": "identical",
  "confidence": 0.88,
  "explanation": "DN, pmax, tmax, рабочая среда совпадают; марка аналогична",
  "deviations": []
}
```

`equivalence_level`: `identical` | `homogeneous` | `not_equivalent` (по ЕОМУ п.3.3.1.3.2).

## Стадия 7 — ReportRow по Шаблону (Даня, CODE)

**Целевой формат:** `Шаблон отчета.xlsx` (111 колонок).

**Структура Шаблона (4 блока):**
1. исходные данные ресурса.
2. три ИЦИ (контрагент, цена, таможня, страхование, доставка, массы).
3. количество собранных/принятых.
4. расчёты.

**Логистика:** колонки таможни/страхования/прочих/доставки заполняются **нулями** (логистика исключена). Средняя цена МТР — только по цене без НДС.
